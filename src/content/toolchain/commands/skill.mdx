**oxabl 5.10.0 and later.** Earlier versions don't have `oxabl skill`.

`oxabl skill` shows or installs the oxabl **agent skill**: a small folder of instructions, in the Agent Skills format, that teaches a coding agent how to use oxabl on ABL code without exploring the CLI first. The skill is built into the `oxabl` binary, so its text always matches the commands and flags of the version you run. For what the skill is and how to set it up, see [Teach your coding agent oxabl](/toolchain/workflows/agent-skill/).

```sh
oxabl skill show [FILE]
oxabl skill install [OPTIONS]
```

The skill is a `SKILL.md` and a few reference files. `SKILL.md` has this front matter:

```yaml
---
name: oxabl
description: Lint, format, analyse and compile Progress ABL (OpenEdge 4GL) code with the oxabl CLI. Use whenever you read, edit, review or refactor ABL source (.p, .w, .cls, .i, .v files) in an OpenEdge or Progress project; to lint or check it, format it, see its database effects (which tables a program reads, writes or locks), compile or build it with an OpenEdge AVM; or to set up oxabl.toml, include paths, a .df schema or a lint baseline.
metadata:
  oxabl-version: 5.10.0
---
```

`name` is how an agent finds the skill, and `description` is what it reads to decide when to use it. `metadata.oxabl-version` is the version of the binary that wrote the copy. It also marks the copy as one oxabl installed, which matters for [updates](#keep-it-current).

## oxabl skill show

Prints a file of the skill to stdout, with the version filled in.

```sh
oxabl skill show
```

With no argument it prints `SKILL.md`. Name a file to print another one, as `--list` names it:

```sh
oxabl skill show --list
```

```text
SKILL.md
references/build.md
references/check.md
references/explain.md
references/rules.md
```

```sh
oxabl skill show references/check.md
```

| Argument | What it does |
| --- | --- |
| `[FILE]` | The file to print, such as `references/check.md`. The default is `SKILL.md`. Not with `--list`. |
| `--list` | Lists the files of the skill, one per line, instead of printing one. |

A file the skill doesn't have exits `2`. Use `show` to read what an agent will read, or to hand the skill to a tool that doesn't read folders.

## oxabl skill install

Installs the skill for your user, where coding agents look for it. There is no project install: one install serves every project.

```sh
oxabl skill install
```

```text
/home/you/.local/share/oxabl/skills/oxabl: installed
/home/you/.agents/skills/oxabl: linked
/home/you/.claude/skills/oxabl: linked
```

oxabl keeps one copy of the skill, the **store**, in `${XDG_DATA_HOME:-~/.local/share}/oxabl/skills/oxabl/`. That is the data folder oxabl already uses for its install record. Two links point to the store, one for each place agents read skills:

| Link | Read by |
| --- | --- |
| `~/.agents/skills/oxabl` | Codex, pi, OpenCode, GitHub Copilot and the other agents that read `.agents/skills`. |
| `~/.claude/skills/oxabl` | Claude Code. |

The command prints one line for the store and one for each link, with its path and state. Both links are made by default.

```sh
oxabl skill install --agent claude
```

| Option | What it does |
| --- | --- |
| `--agent <agents\|claude\|all>` | Which links to make: `~/.agents/skills/oxabl`, `~/.claude/skills/oxabl`, or both. The default is `all`. The store is always installed. |
| `--check` | Writes nothing. Exits `1` when the store is missing or stale, or a selected link is missing, foreign or points elsewhere. See [Keep it current](#keep-it-current). |
| `--refresh` | Updates the store, and any oxabl copy that stands in for a link, only if they exist. It creates no store and no link. |
| `--force` | Renames a foreign entry to `oxabl.bak-<UTC timestamp>` beside it, and installs. See [Entries that aren't oxabl's](#entries-that-arent-oxabls). |

`--check` can't be combined with `--refresh` or `--force`, and `--refresh` can't be combined with `--force`.

oxabl owns the store and replaces it as a whole. It writes a new folder beside the store and swaps it in, so a failed install leaves the old store whole. A file you add to the store is not kept. The links are absolute symlinks. A link that already points to the store is left as it is, so a new oxabl version updates both agents with one write.

Where a symlink can't be made, such as on Windows without the privilege, oxabl copies the store to the link's path instead and prints the reason on that line. oxabl treats such a copy as its own: `--check` compares it with the skill, and `--refresh` and a new install replace it whole.

The VS Code extension has a command that runs the same install, **oxabl: Install agent skill**. See [Teach your coding agent oxabl](/toolchain/workflows/agent-skill/#install-it).

### Keep it current

The store is *current* when its files equal the skill of the binary you run. After you update oxabl, an older store is *stale*: it still works, but it describes the older commands.

```sh
oxabl skill install --check
```

```text
/home/you/.local/share/oxabl/skills/oxabl: stale (references/check.md differs)
/home/you/.agents/skills/oxabl: current
/home/you/.claude/skills/oxabl: current
```

`--check` writes nothing and exits `1` when the store is missing or stale, or a selected link is missing, foreign or points elsewhere. To bring the store up to date without creating anything new, run:

```sh
oxabl skill install --refresh
```

```text
/home/you/.local/share/oxabl/skills/oxabl: updated
/home/you/.agents/skills/oxabl: current
/home/you/.claude/skills/oxabl: current
```

`--refresh` skips what isn't there and what isn't oxabl's, and says so on its line:

```text
/home/you/.local/share/oxabl/skills/oxabl: skipped (not installed)
/home/you/.agents/skills/oxabl: skipped (not installed)
/home/you/.claude/skills/oxabl: skipped (not installed)
```

A link you removed stays removed. `oxabl self-update` runs `oxabl skill install --refresh` after it replaces the binary, so the store follows the binary on its own.

### Entries that aren't oxabl's

A link is *current* when it is a symlink to the store. Anything else at a link's path is **foreign**: a real folder, a file, or a symlink to somewhere else. A store whose `SKILL.md` oxabl didn't install is foreign too. `install` refuses a foreign entry, writes nothing at all, not even the store, and exits `2`:

```text
error: not installed by oxabl: /home/you/.claude/skills/oxabl (a directory without SKILL.md); nothing was written (use --force to rename it to oxabl.bak-<timestamp> and install)
```

`--check` reports the same entry as `foreign` and exits `1`:

```text
/home/you/.local/share/oxabl/skills/oxabl: current
/home/you/.agents/skills/oxabl: current
/home/you/.claude/skills/oxabl: foreign (a directory without SKILL.md)
```

With `--force`, oxabl renames the foreign entry to `oxabl.bak-<UTC timestamp>` beside it, never deletes it, and links:

```text
/home/you/.local/share/oxabl/skills/oxabl: current
/home/you/.agents/skills/oxabl: current
/home/you/.claude/skills/oxabl: linked (the foreign entry is kept as /home/you/.claude/skills/oxabl.bak-20261124T210134Z)
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | `show` printed. `install` wrote, or found nothing to change. |
| `1` | With `install --check`: the store is missing or stale, or a selected link is missing, foreign or points elsewhere. |
| `2` | A usage or I/O error: a file the skill doesn't have, flags that can't be combined, a folder that can't be written, a foreign entry without `--force`, or no `HOME`. |
