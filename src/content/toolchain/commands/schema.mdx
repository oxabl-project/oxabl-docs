`oxabl schema` prints the JSON Schema of [`oxabl.toml`](/toolchain/configure/oxabl-toml/) to stdout. An editor that reads JSON Schema uses it to complete keys, show each key's description and mark mistakes while you edit the file.

```sh
oxabl schema
```

The command has no options and reads no files, so it prints the same schema from any directory. It's generated from the same definitions oxabl reads `oxabl.toml` with, so it lists every `[workspace]` and `[build]` key of the version you run, and it can't drift from what that version accepts. The output is a JSON Schema draft-07 document of about 45 KB. It starts like this:

```json
{
  "$comment": "GENERATED by `oxabl schema` from the oxabl config structs — DO NOT EDIT. Regenerate with `cargo run -p oxabl -- schema`.",
  "$schema": "http://json-schema.org/draft-07/schema#",
  "additionalProperties": false,
  "definitions": {
```

Its tables have `additionalProperties: false`, as oxabl itself rejects a key it doesn't know. A misspelled key shows as a mistake in the editor, where `oxabl check` would exit `2`.

## Use it in an editor

Save the schema next to the file, then point the editor at it:

```sh
oxabl schema > oxabl.schema.json
```

With [Even Better TOML](https://marketplace.visualstudio.com/items?itemName=tamasfe.even-better-toml), the extension for VS Code that gives TOML completion and validation, add a schema directive as the first line of `oxabl.toml`:

```toml title="oxabl.toml"
#:schema ./oxabl.schema.json

[workspace]
name = "acme"
```

The oxabl VS Code extension does this for you. It ships the schema and associates it with every `oxabl.toml` through Even Better TOML's settings, so a project needs no directive. Other editors take a schema file through their own TOML or JSON Schema setting; `oxabl schema` prints the file.

Regenerate the file after you update oxabl, so completion matches the version you run.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | The schema was printed. |
| `2` | An argument the command doesn't take. |
| `6` | The schema couldn't be serialized. It says why on stderr. |
